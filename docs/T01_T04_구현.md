# T01~T04 구현과 검토 방법

2026-09-03. 미완료 목록에서 정한 T01 → T02 → T03 → T04를 구현했다. 지표 규칙과 가설 수를 늘리는 작업이 아니라 조사 근거를 연결하고 결론의 누락·모순을 검사하는 작업이다.

## 구현 결과

| 작업 | 입력·실행 경로 | 검증하는 것 |
|---|---|---|
| T01 계통 연결 | `ElectricalSystemModel`, `ConnectionRecord`, `SupplyPathAssessment`, `ComponentExamination` | 확인된 공급 연결만 경로 조회에 사용. 미확인 연결과 검토하지 않은 공급원을 완료로 세지 않음 |
| T02 보호장치 | `DeviceStateRecord`, `ElectricalEventRecord` | 발견 OFF/TRIP, 자동 동작, 수동 조작, 교체·제거·개조를 분리. 발견 상태에서 발화 전 비통전이나 부동작을 도출하지 않음 |
| T03 시간선 | `EventTimeOrderRuleShape`, `LocalArcFireSequenceRuleShape`, `SupplyTimelineConflictShape`, `PowerRecordCoverage` | 시간 범위·공급원·복전 이력의 조건을 비교. 같은 위치의 아크·화염 도달 선후만 기존 F-2에 전달 |
| T04 연료·열전달 | `FirstFuelAssessment`, `HeatTransferAssessment`, 결론 제약 2개 | 후보의 미확인은 허용. 최종 결론은 동일 가설·연료·발열원의 확인 근거를 요구 |

원문 대응은 `scripts/nfpa.py`, `scripts/silmu.py`, `scripts/babrauskas.py`, `scripts/domestic.py`에 갱신했다. 한 원문 행에 남은 내용이 있으면 `일부`로 유지하여 T05·T07·T14·T15·T16·T24에 연결했다. 현재 집계는 [TBox 미완료 목록](TBox_미완료_목록.md)과 `make status`에서 확인한다.

## 실행 예제

입력은 [합성 조사 예제](../examples/investigation_t01_t04.json)다. 실제 사건의 사실이나 조사관 검토 결과를 대신하지 않는다.

```powershell
$env:PYTHONIOENCODING='utf-8'
python scripts/investigate.py examples/investigation_t01_t04.json --output build/investigation_t01_t04_report.json
```

이 예제에는 계량기→차단기→콘센트→하류 부하의 확인 연결, 별도 공급원의 미확인 경로, 차단기 발견 OFF, 조사 중 전원 격리, 고무 절연 취급, 발생 시각 미상의 아크 기록, 미확보 AMI 기록, 연료·열전달 검토가 들어 있다.

예상 결과는 `conforms: true`, 공급 경로 질문 1개, 시간·전력 기록 질문 2개다. 이 경우 `conforms`는 미확인을 보존한 조사 입력이 제약을 만족한다는 뜻이다. 예제는 최종 결론을 제출하지 않으며 미확인 내용을 조사할 질문이 남는다.

최종 결론의 검증을 요청하려면 세션의 `proposed_conclusion`에 등록된 가설명을 넣는다. 그러면 연료·열전달 제약을 포함한 기존 결론 제약 전체가 적용된다. 이 필드를 점수에 따라 자동으로 채우지 않는다. 오류가 있으면 실행 도구는 종료 코드 1과 해당 제약·대상·메시지를 반환한다.

## 입력 의미

모든 조사 기록에는 `id`, `status`, `attributed_to`, `source`가 있다. 관찰 시각 `observed_at`과 사건 발생 범위 `earliest`·`latest`는 다른 값이다. 시각을 넣을 때는 시간대가 필요하며, 알 수 없으면 비워 둔다. 입력에서 도출 결과인 `pathConnected`나 `recordPrecedes`를 임의로 지정할 수 없다.

`system.components`의 식별자는 해당 세션·계통 모델에 한정된다. 공급원·계량기·보호장치·회로·도체·단자·콘센트·개폐기·부하·전선관·접지면 등을 연결한다. `container`는 함체 또는 콘센트 내장 보호장치처럼 설치 관계를 기록하고, `circuit`과 `role`은 회로와 도체·단자의 역할을 기록한다. `Supply`, `Grounding`, `SwitchControl`, `Protection`을 분리하며 접지나 제어 연결을 공급 연결로 세지 않는다.

`system.paths`에는 검토할 공급원과 대상을 명시한다. 다른 공급원이 모델에 있는데 경로 검토를 생략하면 `systemReviewComplete` 주장을 통과시키지 않는다. 부분 조사와 미확인 경로는 보존할 수 있다. 구조적 경로가 연결되었다고 실제 통전이나 착화 역량이 증명되는 것은 아니다.

구성요소 검사는 `examinations`에 기록한다. 손상 관찰·무손상 관찰·접근 불가·미확인, 아크 지점 관찰 상태와 절연 재질을 구분한다. 아크 미발견과 사후 고무 균열에서 발화 전 사건을 추정하지 않는다. 분전반 내부·외부의 비교 해석과 구체적인 13개 형태 대응은 T05에 남아 있다.

## 시간선의 판단 경계

- 사건 A의 가장 늦은 가능 시각이 B의 가장 이른 가능 시각보다 앞설 때만 시간에 의한 선후를 만든다. 같거나 겹치면 자동 선후를 만들지 않는다.
- 아크와 화염 도달의 실제 `time:before` 관계는 같은 세션·같은 구성요소에 대한 확인 기록에서만 만든다. 관찰 시각으로 발생 시각을 대신하지 않는다.
- 차단 후 아크의 모순 검사는 동일 공급원, 확인된 차단·아크 시간 범위, 해당 기간의 완전한 복전 이력을 요구한다. 복전 가능 시각이 겹치거나 미확인 복전 기록이 있으면 단정하지 않는다.
- AMI 기록의 미확보는 정전 또는 복전이 없었다는 근거가 아니다. 공급자 API와의 실제 연동은 이번 구현에 포함하지 않는다.

검증은 서로 맞지 않는 기록을 재검토 대상으로 표시한다. 이 결과만으로 가설을 기각하거나 전기적 발화 원인을 확정하지 않는다.

## 연료·열전달의 판단 경계

`first_fuels`는 발화 당시 최초 착화물의 존재·위치 근거이며 `heat_transfers`는 해당 가설의 실제 발열원과 같은 연료를 가리킨다. 열전달 설명, 열 충분성, 가열 지속 시간, 연료 상태·배치의 근거를 받는다. 근거는 사건 기록·시험·적용 가능한 분석에 대한 설명일 수 있으며 공통 시간·온도 문턱을 임의로 추가하지 않았다.

기존 `first_fuel`만 있거나 `heatTransferPath` 문자열과 온도만 있는 최종 결론은 새 제약을 만족하지 않는다. 기존 확정용 ABox는 출처가 있는 평가 기록을 보완해야 한다. 후보와 150건의 기존 점수 평가 입력에는 새 필드가 필수가 아니다.

검사기는 기록 간 연결·확인 상태·필수 근거·시간 모순을 검사한다. 작성된 설명의 과학적 타당성, 계측 품질, 실제 발화 가능성은 조사관 및 필요한 전문 검토를 계속 거친다.

## 검증과 후속 작업

`tests/test_investigation.py`의 11개 시험은 하류 공급, 복수 전원, 미확인 연결, 사후 OFF, 복전·시간 겹침, 관찰/형성 시각, 다른 위치의 화염, 후보/결론 구분, 연료 상충, 온도만 있는 입력을 검사한다.

T01~T04 구현 시점에 전체 **88개 시험 통과**, OWL DL 불만족 클래스 **0개**, lint **0건**을 확인했다. 기존 150건은 **정확 126·오판 8·판단보류 16**으로 유지됐다. 예제는 공급 경로 질문 1개·시간/전력 기록 질문 2개를 반환했고 미완료 목록의 행·근거 연결 검사도 통과했다.
