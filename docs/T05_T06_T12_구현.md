# T05·T06·T12: 비교 관찰, 조사 설계, 금속분 부착

2026-09-03. T01~T04의 계통·사건·출처 기록 위에 구현했다. 이번 변경은 조사 기록의 연결과 완료 주장 검증이다. 가설 9개·지표 104개의 원인 판정 체계는 유지한다.

## 실행

```powershell
python scripts/investigate.py examples/investigation_t05_t06_t12.json --output build/investigation_t05_t06_t12_report.json
```

예제의 모든 출처는 `[합성 예제]`다. 실화재 검증 자료가 아니다. 결과의 `issues`는 SHACL 위반·권고이고, `detail_questions`는 비교·계획·검토·부착 사건열에서 추가 확인할 기록이다. `conforms: true`는 입력과 완료 주장이 현재 제약을 통과했다는 뜻이며, 발화 원인이 밝혀졌다는 뜻이 아니다. 미완료 계획이나 미확인 비교를 저장하면 추가 질문이 남을 수 있다.

입력에는 `comparisonContextComplete`, `planVerificationSupported`, `reviewCoverageSupported`, `preIgnitionDepositionSequence`를 직접 쓰지 않는다. SHACL이 기록의 연결 상태를 산출한다. 출처와 시간이 바뀌면 새 입력 그래프에서 다시 검증한다.

## T05 — 접속부·분전반 비교

`heating_observations`에는 구성요소, 원문 항목 번호(1~13), 확인 상태, 상세 관찰, 출처를 기록한다. NFPA §9.10.3.1은 특징이 하나 이상 나타날 수 있다는 설명이다. 13개를 모두 충족해야 한다는 체크리스트나 원인 전용 단서 목록으로 만들지 않았다.

| 번호 | 원문 특징의 요지 | 기존 어휘와의 관계 |
|---|---|---|
| 1 | 동등한 화재 노출을 받은 동종 금속보다 심한 산화 | 국부 변색과 관련하지만 비교 조건이 추가로 필요 |
| 2 | 접속 도체·단자의 패임 또는 질량 소실 | 관찰 항목으로 기록 |
| 3 | 금속 결손 또는 도체 분리 | 관찰 항목으로 기록 |
| 4 | 산화물 성장에 따른 도체·질량 팽창 | `CuprousOxideGrowth`와 부분 대응. 모든 팽창을 아산화동으로 분류하지 않음 |
| 5 | 접속부 인접 재료의 열손상·탄화 | `LocalizedHeatWithSurroundingDamage`와 부분 대응 |
| 6 | 연결 도체를 따라 전달된 열에 의한 피복 탄화·소실 | 방향·위치를 상세 기록 |
| 7 | 손상부와 비손상부의 선명한 경계 | 관찰 항목으로 기록 |
| 8 | 인접 표면의 용융 산화물 비산 흔적 | 금속분 비산과 동일시하지 않음 |
| 9 | 산화물 필라멘트 잔존 | 관찰 항목으로 기록 |
| 10 | 직렬 아크·파팅 아크 흔적 | 기존 `ArcMeltMark`와 관련. 시간·원인은 별도 |
| 11 | 취성 산화물 덩어리의 분리·파절 | `MoltenOxideMass`와 관련. 사후 파절 가능성 유지 |
| 12 | 응고 산화물 표면의 띠·물결 | `OxideBanding` 대응 |
| 13 | 금속 비드와 닮은 응고 산화물 방울 | `MoltenOxideMass`와 관련. 외관만으로 금속 비드라고 확정하지 않음 |

대응 관계는 주석이며 클래스 동일성이나 가점 규칙이 아니다. 기존 나사머리 비대 산화(`EnlargedScrewHeadOxidation`, §9.10.3.3)는 그대로 유지한다.

`comparisons`는 실제 비교의 양쪽 구성요소·위치·손상·노출 근거를 연결한다.

- `MetalExposure`: 같은 재질 표기와 동등 노출의 확인이 필요하다. 미확인은 산화가 없었다는 뜻이 아니다. 1번 특징을 `Confirmed`로 기록하려면 같은 대상을 다룬 확인된 비교가 필요하다.
- `PanelInsideOutside`: 같은 계통에서 내부 대상의 함체와 명시적인 내부·외부 위치를 확인한다. 외부 대상의 함체 칸이 비어 있다는 이유만으로 외부라고 추정하지 않는다. 분전반 안팎의 노출 조건은 기록하되 같았다고 요구하지 않는다.

`assessment_complete: true`는 비교 조건을 확인했다는 주장이다. 누락되거나 모순된 조건은 위반으로 보고한다. 비교 기록과 단독 산화·분전반 아크 관찰을 `hasFact`에 자동 등록하거나 발화 원인으로 확정하지 않는다 (§9.6.4.1·.3).

## T06 — 조사 문제에서 검증·기술 검토까지

`problems`의 문제 진술 → `plans`의 범위·방법·필요 전문성 → `verifications`의 수행 결과·사용한 조사 기록을 연결한다. 계획의 `complete: true`는 출처가 있는 문제와 실제 검증 결과·확인된 근거 연결을 요구한다. 문제를 해결했다고 단정하거나 가설을 참으로 만든다는 뜻이 아니다.

관측 근거의 `ConfirmedAbsent`도 확인된 부재로 인용할 수 있다. `Missing`·`Unverifiable`은 확인된 부재가 아니다. 계획·문제 진술·다른 검토 의견을 관측 근거 대신 인용해 검증 완료를 만드는 것은 막는다.

`technical_reviews`에는 실제 검토자와 요청받은 계획 범위를 지정한다. `scopes`는 그 검토자가 각 범위를 검토할 전문성의 근거, 해당 자료 접근 상태와 근거, 실질 비평을 각각 기록한다.

- `scope_kind: Selected`는 지정한 범위만 다룬다. 다른 분야의 미검토를 전체 검토 완료로 표현하지 않는다.
- `scope_kind: All`은 세션의 모든 계획을 요청 범위에 포함해야 한다.
- `complete: true`는 각 요청 범위의 확인된 전문성·자료 접근·비평 기록을 요구한다. 이름이나 전반적인 자료 접근 체크만으로 대신할 수 없다.
- 전문성의 내용은 해당 범위와 교육·경험 등을 근거로 검토자가 설명한다. 특정 국가의 자격증, 경력 연수, 보편적인 자격 문턱을 만들지 않았다. 근거 문장의 실질적 적합성을 소프트웨어가 인증하지는 않는다.

기존 `TechnicalReview`는 검토 활동이며 새 `TechnicalReviewRecord`는 그 활동에 관한 기록이다. 행정 검토·동료 검토와의 구분, 자료 접근, 조사자와의 관계 공개도 기존 제약을 사용한다. 완료 표시는 검토 대상 결론에 대한 동의나 조사관의 실제 서명을 대신하지 않는다.

## T12 — 접점 아크 금속분과 후속 절연파괴

다음 관계를 하나의 `depositions` 기록으로 연결한다.

```text
접점 아크 사건 → 특정 절연면에 금속분 부착 → 같은 면의 절연파괴 → 발화 사건
```

각 사건의 발생 시간 범위·확인 상태·동일 세션/계통과 발생원-부착물 연결 근거를 대조한다. 부착물 관찰의 출처와 아크 발생원을 지목한 근거는 별도 칸이다. 관찰 시각은 발생 시각의 대용이 아니다. 접점 아크는 일반적인 미상 아크와 구분한 `ContactArcOccurrence`로 입력한다.

앞 사건의 최종 가능 시각이 다음 사건의 최초 가능 시각보다 이른 경우에만 `preIgnitionDepositionSequence`를 산출한다. 시간이 겹치거나, 발생원·대상이 다르거나, 사후에 부착됐거나, 발생 시각을 모르면 확인 질문을 남긴다. 실제 부착은 아크 발생 도중 일어날 수도 있으므로 이 엄격한 선후 조건을 충족하지 않는다는 이유로 사건의 물리적 가능성을 부정하지 않는다.

산출값은 확인된 기록상 사건열이다. 부착물이 실제로 절연파괴를 유발했는지, 발화에 필요한 에너지·연료 조건이 있었는지는 추가 감식과 T04 검토 대상이다. `ContaminatedEnvironment` 선행 조건이나 트래킹 원인·가점을 자동 생성하지 않는다.

### 원문 대조에서 바로잡은 점

이번에 확인한 화재조사실무Ⅳ PDF의 **인쇄 p.261, 3.3.5 가1**은 접점 아크의 비산 금속분이 절연물에 부착해 절연파괴를 일으킬 수 있다고 설명한다. 이 부분이 T12의 근거다.

**인쇄 p.211, 3.1.5 바**는 반복적인 접점 아크에 의한 주변 절연재 열화·트래킹 사례이며, 금속분 부착을 명시하지 않는다. 이 행을 T12의 금속분 경로로 완료 처리하던 계획을 정정하고 **T13(기존보류)**에 연결했다. 열적 열화에서 시작하는 트래킹 필요조건은 이번에 바꾸지 않았다.

쪽수는 이 PDF의 인쇄 표기를 직접 확인했다. 기존 목록의 시작 쪽수·일괄 오프셋으로 다시 계산한 숫자가 아니다.
