# TBox 재편 계획 — 절 순서와 기록 도형의 분리

작성 2026-09-04. 대상은 구조 문제 둘이다.

1. TTL 이 주제가 아니라 작업 순서로 쌓여 있다 (57절, 5110줄. 29·35·36·41·47절은 고친 기록이 절 제목).
2. T01~T15 의 기록 도형(42개, 전체 128개의 1/3)이 추론 어휘와 한 파일에 섞여 있다.

## 원칙

- **의미를 바꾸지 않는다.** 재편 전후 그래프가 동형(isomorphic)이어야 한다. 이것이 유일한 완료 조건이다.
- **손으로 옮기지 않는다.** 주어 블록 단위로 스크립트가 옮긴다. 5000줄을 손으로 잘라 붙이면 반드시 빠진다.
- **규칙 순서는 파일 순서가 아니다.** `sh:order` 가 정한다. 그래서 블록을 옮겨도 판정이 안 바뀐다. 이것을 0단계에서 시험으로 확인한 뒤 시작한다.
- **줄 번호로 가리키지 않는다.** 문서·backlog 는 앵커 문자열로 가리킨다. `scripts/backlog.py` 는 이미 그렇게 한다.
- **한 단계에 한 커밋.** 각 단계 끝에 `make test` · `make lint` · `make reason` · 동형 검사가 통과해야 한다.

## 0단계 · 기준선 — 완료 2026-09-04 (커밋 `b0b9ec8` 위)

T16 커밋(`b0b9ec8`) 뒤에 시작했다. 계획대로 넷을 했고 예정에 없던 것 둘이 나왔다.

1. `scripts/isomorphic.py` — `make iso` / `make iso-freeze`. 기준선은 `build/baseline.json`(git 밖). 재편을 시작하기 전에 굳힌다.
2. `scripts/ttlblocks.py` — 주어 블록 파서. 2단계의 도구다. 왕복(cut → join)이 원본과 바이트 단위로 같아야 하고 실행하면 그것부터 확인한다. 현재 블록 1371개, 주어 있는 것 1350개.
3. **순서 무관성 증명 완료.** 씨앗 셋으로 본문 1355 블록을 섞어 전부 동형이었고, 씨앗 7 로 온톨로지를 바꿔 치고 시험 204개 전부 통과, 150건 평가 결과가 기준과 한 글자도 다르지 않았다. **파일 순서에 기대는 곳은 없다.** 2단계에서 블록을 옮겨도 판정은 안 바뀐다.
4. `scripts/_utf8.py` — stdout·stderr 를 utf-8 로 고정한다. CLI 스크립트 20개가 부른다. `status.py` 가 em-dash 하나에 죽던 것이 고쳐졌다.

### 0단계에서 드러난 것 둘 — 계획에 없던 것

**rdflib 의 `to_isomorphic` 은 이 그래프에 못 쓴다.** 빈 노드 932개 중 `sh:property [ sh:path …; sh:minCount 1 ]` 처럼 구조가 닮은 것이 많아 정규화가 수렴하지 못한다. 블록 순서만 바꿔도 '동형 아님'을 내는데 접지 트리플 4716개는 전부 같았다. 그래서 빈 노드마다 재귀 서명을 만들어 다중집합으로 비교하도록 바꿨다. 이 그래프의 빈 노드는 명명 주어에 매달린 나무라서 가능하다.

**CRLF 가 SPARQL 규칙의 값을 바꾼다 — `.gitattributes` 를 더했다.** `core.autocrlf=true` 인데 `.gitattributes` 가 없어서, 저장소는 LF 로 두고 체크아웃할 때 CRLF 로 바꿨다. 삼중따옴표 안의 SPARQL 문자열이 통째로 리터럴이므로 **같은 커밋인데 그래프가 달라진다** — 실제로 134개 트리플이 갈렸다. 시험은 통과한다(SPARQL 이 `\r` 을 공백으로 보므로). 그러나 이 상태로는 동형 검사가 성립하지 않고, Windows 에서 클론한 사람은 시험된 것과 다른 그래프를 받는다. `* text=auto eol=lf` 로 고정하고 `git add --renormalize` 를 돌렸다. 재편 스크립트도 반드시 `newline="\n"` 으로 쓴다.

## 1단계 · 기록 도형 분리 (문제 2, 하루)

파일을 둘로 나눈다.

```
ontology/efi_tbox.ttl            추론 어휘. 4축·가설·사슬·지표·M/F/C/D 도형·원문 이식
ontology/efi_investigation.ttl   조사 기록. 현재 50~57절 (T01~T15). 기록 클래스·완비 도형·SHACL 만
```

기준: **점수·반증·형성(D-15)·결론(C-)에 닿는 것은 tbox, 기록의 완비만 검사하는 것은 investigation.** 경계에 있는 것(예: T02 의 보호장치 발견 상태에서 통전 사실을 만들지 않는 규칙)은 tbox 에 둔다 — 추론에 닿기 때문이다.

1. `src/efi_schema.py` 에 `load_graph(paths=None)` 을 하나 둔다. 기본값은 `ontology/*.ttl` 전부. 19곳의 `Graph().parse(TTL)` 을 이 함수로 바꾼다. 경로 상수 `TTL` 은 그대로 두되 목록으로 바꾼다.
2. HermiT(owlready2)와 외부 도구는 파일 하나를 받는다. `make reason` 앞에 `scripts/bundle.py` 가 `build/efi_all.ttl` 로 합친다. 헤더의 `owl:imports` 에 `<efi_investigation.ttl>` 을 더하지 않는다 — 상대 경로 import 는 도구마다 해석이 다르다.
3. 50~57절을 그대로 잘라 새 파일로 옮긴다. 접두어 헤더를 복사한다. 동형 검사.
4. `scripts/lint.py` 에 파일 구분을 넣는다. investigation 의 어휘는 "사슬에 안 붙은 어휘" 로 세지 않고 **"기록 전용 어휘"** 로 따로 센다. `make status` 에 그 수를 보인다. 이것이 문제 2 의 핵심이다 — 기록 어휘가 자라는 것을 숨기지 않고 추론 어휘와 구분해 보이게 한다.
5. 시험 하나를 더한다: investigation 파일의 어떤 자원도 `scoreDelta`·`canManifest`·`enables` 의 주어나 목적어가 아니다. 경계가 무너지면 잡는다.

## 2단계 · 절 재편 (문제 1, 이틀에서 사흘)

### 목표 배치

주제로 묶고, 출처는 각 블록의 `rdfs:comment`·`dcterms:references` 에 남긴다 (이미 그렇게 돼 있다). 고친 기록(29·35·36·41·47절 제목)은 절에서 사라지고 `docs/변경이력` 으로 간다.

```
A. 머리말 · 접두어 · owl:Ontology
B. 상위 정렬 (BFO) · 보조 축 (SOSA · PROV-O · Time · 상태 열거)
C. 축 ① 발열 메커니즘 — 정의 메커니즘 열둘과 배타 공리를 한자리에
D. 축 ② 물리 증거물 · 손상 양상 · 관찰 정의 (용흔 외관, 표 4-9, 오인되는 것들, 안팎 판정)
E. 축 ③ 선행 조건
F. 축 ④ 최초 착화물
G. 객체 속성 · 데이터 속성
H. 가설 아홉 — 가설마다 한 블록:
     H.1 접촉불량  H.2 압착손상  H.3 반단선  H.4 절연열화  H.5 트래킹
     H.6 외부화염  H.7 과부하·과전류  H.8 누전·지락  H.9 층간단락
     각 블록 = 정의(≡) · 필요조건(⊑) · canManifest · 지표 규칙 sup/ref · 그 가설 전용 D- 도출
I. 인과 사슬 — enables · producesDamage · ignites · attests (가설 블록에 안 들어가는 교차 선언)
J. 방법론 층 — NFPA 절차. M- · F- · C- · 공통 D- 도형. sh:order 순서대로
K. NFPA 921 조항 자원 (현재 12절)
L. 아직 사슬에 붙지 않은 것 · 보류 (lint 가 세는 것들의 임시 거처. 비어 있어야 정상)
```

### 방법

1. `scripts/reorg.py` 를 만든다. TTL 을 **주어 블록**으로 자른다. 블록 = 직전 주석 줄들 + 주어 첫 줄부터 `.` 로 끝나는 줄까지. 파일이 한 줄 한 주어 규칙을 지키므로 가능하다. 절 제목 주석(`# N. …`)은 버린다.
2. 블록마다 목적지를 정하는 표를 스크립트 안에 둔다. 판정 순서:
   - `a efi:IndicatorRule` → `efi:targetScenario` 의 가설 블록 H.n
   - `a sh:NodeShape` → `sh:name` 접두어. D- 중 특정 가설만 보는 것은 H.n, 나머지는 J
   - `a owl:Class` → `rdfs:subClassOf` 를 따라 올라가 4축 중 어디인지. 가설이면 H.n
   - 속성 → G
   - `dcterms:references` 대상인 NFPA 자원 → K
   - 못 정한 것 → L 로 보내고 목록을 출력한다. **L 이 비지 않으면 표를 고친다.** 손으로 배치하지 않는다.
3. 절 안 순서는 원래 파일 순서를 유지한다 (안정 정렬). 옮기기만 하고 다시 쓰지 않는다.
4. 실행 → 동형 검사 → `make test` → 150건 평가 동일 → 커밋. 한 번에 다 옮긴다. 절 하나씩 옮기면 중간 상태가 더 읽기 어렵다.
5. 각 블록 머리에 안정 앵커 주석을 둔다. `## [H.3 반단선]` 형태. 문서는 이 문자열로 가리킨다.

### 재편에서 드러날 것

- 같은 가설의 정의가 6절과 48절, 33절에 흩어져 있던 것이 한 블록으로 모이면 **중복 선언과 서로 어긋난 주석**이 나온다. 그것은 고칠 것이지만 이 단계에서 고치지 않는다. 목록만 적어 3단계로 넘긴다. 이 단계는 동형이어야 한다.
- 어느 가설에도 붙지 않는 지표 규칙이나 D- 도형이 L 에 남으면 그것이 lint 가 못 보던 끊긴 사슬이다.

## 3단계 · 참조 갱신 (하루)

1. `python scripts/backlog.py --write` 로 줄 번호 재생성. 앵커가 안 잡히는 항목이 있으면 앵커 문자열을 고친다.
2. `CLAUDE.md` · `docs/인계.md` · `docs/T*_구현.md` 의 "TTL N절" 표현을 앵커 이름으로 바꾼다. grep `[0-9]+절`.
3. `scripts/status.py` 가 절 목록을 새 앵커에서 읽게 한다.
4. 2단계에서 적어 둔 중복·어긋남 목록을 하나씩 닫는다. 이때부터 동형이 아니어도 되지만 각 변경은 따로 커밋하고 `make test` 를 통과해야 한다.

## 4단계 · 되돌아가지 않게 (반나절)

시험 셋을 더한다.

- `test_indicator_rule_lives_in_its_hypothesis_block`: 지표 규칙이 `targetScenario` 의 앵커 블록 안에 있다. 파일을 앵커로 잘라 확인한다.
- `test_investigation_file_never_touches_scores`: 1단계 5번.
- `test_section_l_is_empty`: L 블록에 주어가 없다.

## 하지 않는 것

- 파일을 셋 이상으로 나누지 않는다. 가설별 파일은 교차 선언(enables 등)이 어디 있는지 찾기 어렵게 한다.
- 어휘 이름을 바꾸지 않는다. 이름 변경은 사례 150건·문서·Python 을 다 건드린다. 별도 작업.
- 2단계에서 의미를 고치지 않는다. 동형이 깨지는 순간 재편과 수정이 섞여 무엇이 무엇을 바꿨는지 알 수 없다.

## 위험

| 위험 | 대응 |
|---|---|
| Codex 가 같은 파일을 고치는 중 | 0단계 전에 커밋을 받는다. 재편 중에는 TTL 작업을 멈춘다. 2단계는 하루 안에 끝낸다 |
| 빈 노드 때문에 동형 검사가 느리거나 실패 | 7천 트리플이면 `to_isomorphic` 으로 초 단위. 실패하면 `graph_diff` 로 어느 트리플인지 본다 |

| 절 번호를 든 문서를 놓침 | 3단계에서 `[0-9]+절` grep. `make backlog` 가 앵커 없는 참조를 오류로 낸다 |
